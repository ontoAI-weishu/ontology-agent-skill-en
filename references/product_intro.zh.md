# 本体论智能体（Ontology Agent）· 产品介绍

> 本文是技能包面向用户/渠道/投资人的统一介绍文案。定位、三模式、数字孪生与 AI-FDE 愿景均基于已落地能力，不做夸大；规模与严谨度不及一线大厂，但同谱、可延展。

---

## 一、一句话定位

**本体论智能体，是一套"把任意企业变成可运行数字孪生"的通用引擎。**

你装上它、用自然语言描述自己的公司，它就自动把这家公司建成一支 AI 专家团 + 一张可读写、可执行、可闭环的业务知识网——并且**同一套"公司大脑"可以无缝切换到三种部署形态**。

> 装一个 Skill，把你的公司变成一套会自己干活的智能体系统。

---

## 二、真正的核心 IP：厂商中立的「本体论规范」

市面上大多数 AI 工具卖的是"外壳"（某个 App、某个平台）。我们卖的是里面的**规范层**——一套厂商中立、可移植的企业本体论：

- **语义层**：把企业的人、部门、客户、订单、合同、设备……定义成有关系的"业务实体"（不是冷冰冰的表格字段）。
- **逻辑层**：把核心业务流程（接单→生产→交付→回款）写成可编排的状态机与函数。
- **决策层**：把"谁能做什么、红线在哪、什么时候要老板确认"写成治理规则。
- **动作库**：141 条可直接调用的企业动作（开票、报税、舆情监控、风险预警……）。
- **24 部门库 + 行业包 + 私有定制**：通用骨架 + 行业风味 + 你的专属微调。

这套规范是**纯数据（YAML）**，不绑定任何运行平台。这意味着——

> **它不是只能在一个地方跑的软件，而是可以随身带走、换壳即用的"企业操作系统规范"。**

## 三、三种部署形态：一份规范，三种落地

这是本产品区别于普通 AI 工具的关键：**同一套公司大脑，三种交付方式，企业按需升级，不重买、不重搭。**

| 形态 | 本质 | 适合谁 | 数据在哪 |
|---|---|---|---|
| **A · 技能包（当前）** | 规范跑在 WorkBuddy 云运行时，订阅即用、零运维 | 中小企业 / OPC / 想先体验 | 实例本地 + 资料库在云 |
| **B · 云端协同** | "端主内、云主外"：敏感数据留本地，复杂推理与外部检索上云（以面壁 EdgeClaw Box 等为参考实现） | 制造业、受监管行业、有车间、要数据不出域 | 敏感留端、公开情报上云 |
| **C · 纯私有化** | 整套规范 + 运行时全自托管，完全离线（air-gapped），对标 Palantir 气隙部署（以京东 JoyAgent、Dify 等开源框架为参考实现） | 军工 / 政务 / 强合规核心资产 | 全留本地，颗粒不出门 |

**为什么能"完美自洽接入"另外两种？** 因为另外两种运行形态只是把同一套规范装进不同的"运行时外壳"（端侧轻盒子 / 自托管开源框架，如 EdgeClaw、JoyAgent、Dify 等均可作为参考实现），语义、逻辑、决策完全一致，企业换形态时业务大脑不丢失、不重写。我们刻意不把产品绑定任何单一厂商——任何满足"运行时能力契约"的产品都能接入（详见 `references/deployment.yaml` 的 `patterns` 段）。

**那它只能跑在 WorkBuddy 上吗？** 今天，技能的"外壳"是 WorkBuddy 格式，所以直接跑在 WorkBuddy 上；但那层"厂商中立的本体论规范"不依赖任何平台。我们提供了 `adapters.py` 的宿主平台"包装脚手架"（Coze / Dify / Claude / 腾讯元器 / 百度千帆 / WorkBuddy 等），可把同一套规范 port 到不同竞品平台，**规范零改写**——所以我们的真 IP 是"规范"，不是"某个平台的壳"。

## 四、它已经实现了什么：企业级数字孪生 + AI-FDE 自动交付

### 4.1 企业数字孪生（对标 Palantir Ontology）
传统数字孪生是"只读的 3D 模型"。我们做的是**可读、可写、可执行、可闭环的动态业务操作系统**：AI 专家团基于同一份公司事实源协作，发现机会能草拟行动、越权只等你确认——这正是一线大厂 Ontology 的"数字孪生"内核。

### 4.2 AI-FDE：把"驻场工程师"自动化了（对标 Palantir FDE / 中数睿智 AI-FDE）
Palantir 靠 **FDE（Forward Deployed Engineer，驻场工程师）** 深入客户现场、花 6–9 个月搭 Ontology；国内"中国版 Palantir"中数睿智已把它升级为 **AI-FDE**——让智能体当"数字驻场工程师"，承担需求理解、本体建模、规则配置等 80%+ 标准化工作，把交付压到 1–2 个月。

**我们的系统，本质上就是一个开箱即用的 AI-FDE**：渐进式引导（onboarding）自动带企业走完"定义实体 → 建关系 → 配规则 → 可执行动作"的 Ontology 落地全流程。企业主不用懂技术，聊着天就把公司"数字化"了。

> 一句话：大厂用顾问团队数月交付的事，我们用一个 Skill 即时生成。

## 五、应用场景：谁该用

- **一人公司 / OPC、电商、小微**：开箱即用，12 个 AI 员工立刻上岗。
- **制造业工厂**：已内置制造业工厂行业包（含服装 / 食品 / 电子 / 机械 / 化工等 12 细分），生产→质检→交付核心循环 + 安全环保质量红线。
- **事业单位 / 金融机构 / 医疗 / 教育科研**：已内置 4 个横向行业包——事业单位（国资 / 政府采购 / 编制）、金融（AML / 适当性 / 资本监管，红线为参考框架非法律意见）、医疗（人类遗传资源 / GMP / 健康数据）、教育科研（科研经费 / 成果转化）；每个包的行业「心脏」部门可私有定制添加。
- **受监管 / 有车间 / 要数据不出域**：升云端协同，敏感业务本地闭环。
- **军工 / 政务 / 强合规核心**：升纯私有化，完全离线、可审计。
- **想要"好员工"体验的企业**：自主监测 + 自发行为层，让数字公司隔三差五主动挖出与你企业相关的政策、竞品、风险——像真有个好员工在帮你盯着。

## 六、发展空间：它还会长成什么

1. **行业包持续扩充**：已内置 8 个行业包（OPC / 电商 / 小微 / 制造业 / 事业单位 / 金融 / 医疗生物医药 / 教育科研）；后续可继续加能源、物流、农业等。
2. **自主能力深化**：监测与自发行为从"草拟+提醒"走向"授权内自动执行"，数字公司越来越像真实团队。
3. **三模式全谱系覆盖**：从零门槛体验到强合规私有化，一家企业全生命周期的数字化底座。
4. **可移植交付形态**：规范可导出、可卖给其他企业、可 port 到任意端云协同 / 纯私有化运行时（以 EdgeClaw、JoyAgent、Dify 等为参考实现），也可经"包装脚手架"移植到 Coze / Dify / Claude / 元器 / 千帆 等宿主平台——**这是微数的真 IP，也是未来的商业化底座**。

## 七、持续完善：私有化定制自愈 + 反馈

本体论智能体是一套覆盖多行业的企业本体论，体量较大，实际使用中偶有个别语义、逻辑或功能上的细微不足，属正常现象。若你遇到此类情况，无需等待版本更新——直接向你的「经营主理人」描述问题即可：主理人会在**不改动核心本体论规范**的前提下，为你做私有化定制修复，并把修复后的能力保存在你**本地的私有实例**中，相关功能即恢复正常、可长期使用。你的本地定制只属于你，不污染系统内核、也不影响后续升级与跨平台移植。

> 若涉及系统内核级问题（运行时 / 引擎层 bug），主理人会引导你反馈给我们处理；同时，我们也**欢迎你及时将使用中发现的不便反馈给微数**，便于在后续版本中持续改进。

这种「用户描述问题 → 主理人私有化修复 → 存本地 → 功能恢复正常」的机制，让系统在体量大、难免有个别不足的前提下，依然能在你的实际体验中把不足就地解决——这也是我们刻意把「规范」与「实例」严格分离带来的红利。

## 八、与一线大厂的关系：同谱，而非复制

我们与 **Palantir Ontology**（语义+动力+动态层的数字孪生操作系统）、**中数睿智 AI-FDE**（中国版 Palantir 的自动交付）**同属一个谱系**——解决的都是"把企业变成可运行的数字孪生"这一根本问题。

我们的路线差异在于：**以"可移植本体论规范 + 轻运行时"切入**，先借 WorkBuddy 内核零成本交付，同时预留云端协同与纯私有化的出口。这让我们不必像大厂那样重投入底层，却能用同一套规范触达从微型公司到强合规客户的完整光谱。

> **诚实定位**：在交付规模、工程严谨度上我们尚不及一线大厂；但在"让一家企业即刻拥有可运行的数字孪生 + AI 驻场工程师"这一愿景上，我们已同谱、可延展、且先一步做到了开箱即用。
