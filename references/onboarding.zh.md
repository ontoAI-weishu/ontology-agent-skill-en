# 渐进式主动引导（Onboarding）设计说明

> 本体论智能体让「数字公司」拥有 onboarding：**不是等用户主动回忆要交代什么，
> 而是数字公司循序渐进地引导用户补齐企业数据**。用户无需知道该给什么，
> 数字公司自己知道还差什么、一次只问一点点。

## 一、设计原则（为什么这么做）
1. **数字公司拥有引导权**：用户只描述「我是 X 公司」即可起步，其余信息由数字公司按
   优先级主动补采，不在用户脑中塞一张大表单。
2. **循序渐进、一次 1~2 件**：每轮只问最高优先级的 1~2 个缺口，避免一次性轰炸引发反感。
3. **说明用途 + 安全安抚**：每个问题都带「为什么需要」与「数据安全说明」，降低安全顾虑。
4. **可跳过**：用户随时可说「跳过 / 以后再说」，不阻塞真实任务。
5. **不打断主业**：用户有具体诉求时先办正事，引导穿插在任务收尾或自然间隙。

## 二、优先级分层（先补影响最大的）
- **P0（决定所有建议基调）**：公司全称 / 企业类型 / 地区 / 行业 / 规模；老板称呼 / 决策风格 / 风险偏好 / 沟通腔调。
- **P1（核心事实）**：法律形态 / 统一社会信用代码 / 核心工作流 / 授权边界；公司阶段 / 核心产品 / 客户类型。
- **P2（上下文与接口）**：老板专业背景 / 价值排序；使命愿景 / 品牌语气；本季目标 / 在用系统 / 禁忌。
- **P3（持续补采）**：任务执行中暴露的缺口（如要做某事但缺某数据），即问即补。

## 三、节奏
- 新用户前 2~3 次会话：只铺 P0，让用户先「能用」。
- 之后每次会话：最多补 1~2 个 P1/P2，并偶发一句进度播报（如「已补全 60%，还差几块」）。
- 任务触发：做任何具体事若缺数据，只问那一件，办完继续。

## 四、主理人怎么用（运行期）
经营主理人会话开始时 Read `instance.yaml` + `company-memory.md` 后，调用引导引擎：

```bash
# 看进度
python scripts/onboarding.py --instance <公司>/instance.yaml --report
# 取下一个要问的问题（每次限 1~2）
python scripts/onboarding.py --instance <公司>/instance.yaml --next --limit 2
```

把 `--next` 输出的问题，用自然语言、带用途与安全说明地发出，**一次一个**；
用户回答后回写 instance 对应字段（保持 YAML 合法），循环往复直到 coverage=100%。

## 五、示例话术（温和、给理由、给安全）
- 「顺然，咱们先把「您希望我怎么称呼您」定一下？这样 12 位专家跟您沟通都用您习惯的叫法。
  这个信息只存在您本地实例里，不会出域，您随时可改。」
- 「再补一个小点：您做决策更偏数据支撑还是直觉？这决定我给建议时是先甩数据还是直接给结论。
  不涉及任何敏感信息，本地留存即可。」
- 「咱们公司信息已补全约 60%，还差几块（比如本季目标、在用系统）。不急，
  您想起啥说啥，我慢慢记。」
